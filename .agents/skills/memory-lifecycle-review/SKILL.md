# 记忆生命周期复核

本 Skill 负责把多个真实影片 README 中的“本期相关记忆（快照）”汇总成可审查的证据报告。它与其他两个记忆 Skill 的边界必须保持清楚：`creative-memory-review` 负责单期比较并写入候选记忆和本期快照；`memory-query` 负责创作前只读查询当前三份阶段记忆；本 Skill 默认只负责跨期统计和提出状态变更申请，获用户明确批准后再执行对应状态写入。

## 触发条件

用户明确要求以下任一事项时使用：

- 指定两期或多期影片，整理某条记忆的采用次数、验证次数、失败或观察情况；
- 复核记忆是否值得从候选转正式，或正式记忆是否应转暂存；
- 检查记忆登记簿、README 快照和阶段记忆是否一致；
- 明确要求“全量”“所有影片”“整个频道”生命周期复核。

普通的单期归档、写作、润色、查询可用记忆，或只查看播放数据时不要触发。

## 不可越过的边界

1. 默认只读取用户点名的 `episode_id`。只有用户明确要求全量扫描时才使用全库模式；`project/example/README.md` 永远排除。
2. `episode_id` 只能从目标 README 的基础信息读取。目录名、标题、文件名、Git 历史和聊天内容都不能代替它。重复或缺失的 `episode_id` 必须报告，不能猜测。
3. 只把 `## Changelog` 下唯一的 `### 本期相关记忆（快照）` 六列表作为结构化证据。普通 Changelog 的“记忆写入”文字不能计数。
4. 没有快照表的旧 README 标为“历史未结构化”，不计数、不自动映射。把旧记录映射到某个 ID 必须由用户明确提供并另行批准。
5. 快照中的“状态”是该期历史快照，不是当前状态。当前状态从三份阶段记忆文件读取；不能由快照或登记簿的手工数字反推。
6. 本 Skill 在报告阶段只读，不写阶段记忆、README 或登记簿，不升级、不降级、不删除，也不修改历史快照。用户明确批准某项申请后，本 Skill 才能更新对应阶段记忆、登记簿索引和状态历史；历史快照永不回写。

## 开始前读取

按以下顺序读取，避免把旧摘要当成事实：

1. 用户点名的每个真实项目 README；全量模式读取 `project/*/README.md`，排除 `project/example`。
2. 每份 README 的 `episode_id`、`## Changelog` 和快照表；只把快照表用于统计。
3. `memories/大纲记忆.md`、`memories/文稿记忆.md`、`memories/包装记忆.md`，取得当前记忆 ID、阶段和状态。
4. 若存在 `memories/记忆登记簿.md`，读取记忆索引和状态历史，用于完整性检查与展示。登记簿是投影，不覆盖 README 快照计数；缺少登记簿时明确报告证据不完整。
5. 使用 `references/lifecycle-contract.md` 校验表头、结果标签、去重和建议门槛。需要确定性统计时运行只读脚本 `scripts/lifecycle_review.py`，或通过 `scripts/lifecycle_review.ps1` 启动。

## 快照解析与统计

快照表必须有且只有以下六列：

`日期 | 记忆ID | 阶段 | 状态 | 本期结果 | 依据`

每个 README 中同一 `记忆ID` 只能有一行；表头、列数、日期、ID、阶段、状态、结果标签或依据非法时，停止该次统计并指出文件和行号。允许的“本期结果”标签为：`采用`、`已验证`、`失败`、`待验证`、`无法判断`、`明确冲突`、`未采用`。明显矛盾的组合（例如 `采用+未采用`、`已验证+失败`）必须拒绝。

按 `记忆ID + episode_id` 去重。同一行中一个标签对某一计数类别最多贡献一次：

- `采用` → 采用期数；
- `已验证` → 结果支持期数；
- `失败` 或 `明确冲突` → 结果反例期数；
- `待验证` 或 `无法判断` → 观察期数；
- `未采用` → 不增加上述计数。

采用与结果必须分开显示。三期采用但没有“已验证”只表示用户连续采用，不表示效果已被证明。

## 输出报告

先说明统计范围：指定项目时写“范围内计数”，全量模式才可写“全库计数”。报告至少包含：

- 每条涉及记忆的阶段、当前状态、采用期数、结果支持期数、反例期数、观察期数和涉及 episode；
- 未结构化的历史 README、缺少登记簿和完整性警告；
- 用户批准前的状态变更申请；
- 明确不能从现有证据判断的部分。

候选转正式在本次明确统计范围内达到 3 个不同 episode 的“采用”、且当前状态为“候选”时提出申请；报告必须注明这是指定范围计数还是全库计数。效果支持数单独列出，不作为隐含证明；范围内不足三期时不提出申请。

正式转暂存只在证据明确包含“明确冲突”、被替代或用户停用时提出申请。单次 `失败` 只计为反例，不自动触发降级；需要用户确认的替代或停用事实应在依据中明确可追溯。

暂存转候选只能在用户明确要求重新观察某条记忆时提出申请。命令行脚本用 `--reobserve-memory-id`（PowerShell 为 `-ReobserveMemoryId`）显式传入该记忆 ID；没有这个明确请求时不提出恢复申请。

## 用户批准后的协作

本 Skill 的报告结尾只提出一个清晰的批准问题，列明记忆 ID、原状态、新状态、理由和证据。用户未明确批准时保持只读。用户批准后，本 Skill：

- 更新对应阶段记忆的状态；
- 按全量快照重建 `memories/记忆登记簿.md` 的索引计数，并在状态历史中追加最小记录；
- 保持所有历史 README 快照不变；
- 写入前重读申请依据并保存本步骤文件快照；写入后回读并校验编号、阶段、状态、索引计数和状态历史。任一步失败时恢复本步骤变更并停止。

## 推荐命令

```powershell
pwsh.exe -NoProfile -File .agents/skills/memory-lifecycle-review/scripts/lifecycle_review.ps1 -Episode WF-20260808-01 -Episode WF-20260815-01
pwsh.exe -NoProfile -File .agents/skills/memory-lifecycle-review/scripts/lifecycle_review.ps1 -All -Format json
pwsh.exe -NoProfile -File .agents/skills/memory-lifecycle-review/scripts/lifecycle_review.ps1 -Episode WF-20260808-01 -MemoryId SCR-0001 -ReobserveMemoryId SCR-0001
```

脚本的 JSON 输出适合后续自动校验，Markdown 输出适合向用户展示。脚本只读；任何解析错误都以非零退出码返回，不把原始文件全文作为退路。

## 完成标准

完成报告必须明确：本次范围、结构化和未结构化项目、每条记忆的四类计数、当前状态、申请或不申请状态变化的理由，以及登记簿/阶段记忆完整性检查结果。不能把“用户采用”写成“效果已验证”，不能把建议写成已经执行的状态变更。
