# 记忆生命周期契约

本契约定义 `memory-lifecycle-review` 能够统计什么，以及哪些状态变化必须留给用户批准。

## 输入范围

- 默认只处理命令中明确指定的 `episode_id`。
- 只有显式使用 `--all` 才扫描 `project/*/README.md` 全库；`project/example/README.md` 永远排除。
- `episode_id` 必须从 README 的基础信息字段读取，格式为 `WF-YYYYMMDD-NN`。目录名不能代替 README 字段。
- 缺失或重复 `episode_id` 是结构错误；不能用标题、目录名或文件名猜测。

## 快照表

结构化证据只能来自 README `## Changelog` 下唯一的 `### 本期相关记忆（快照）` 表。表头固定为：

```text
日期 | 记忆ID | 阶段 | 状态 | 本期结果 | 依据
```

空表可以没有数据行；模板中的全为 `—` 的占位行也视为空表。旧 README 没有该表时标记为“历史未结构化”，不计数，也不能从普通 Changelog 的自然语言记录自动映射。

数据行规则：

- 日期为 `YYYY-MM-DD`；依据不能为空或仅为占位符。
- 记忆 ID 为 `OUT-0000`、`SCR-0000` 或 `PKG-0000`，并且前缀必须与阶段“大纲、文稿、包装”一致。
- 状态是本期快照，只能为“候选、正式、暂存”；它不是当前全局状态。
- 本期结果允许组合：`采用`、`已验证`、`失败`、`待验证`、`无法判断`、`明确冲突`、`未采用`。
- 禁止明显矛盾的组合：`采用+未采用`、`已验证+失败`、`已验证+明确冲突`。同一 README 同一记忆 ID 重复出现也属于结构错误，不能用最后一行覆盖。

## 统计

按 `记忆ID + episode_id` 去重。各类计数来自不同的 episode 集合：

| 标签 | 计数 |
| --- | --- |
| 采用 | 采用期数 |
| 已验证 | 结果支持期数 |
| 失败、明确冲突 | 结果反例期数；明确冲突同时保留冲突 episode 清单 |
| 待验证、无法判断 | 观察期数 |
| 未采用 | 不计入上述四类 |

同一行包含多个标签时，每个计数类别最多贡献一次。采用和效果支持始终分开展示；采用三期不等于效果已验证三期。

## 状态建议

- 当前三份阶段记忆中的状态为“候选”、且本次明确统计范围内采用期数达到三个不同 episode 时，输出候选→正式申请；报告必须标明是指定范围计数还是全库计数。
- 指定范围不足三期时不输出正式申请；指定范围达到三期时可以申请，但不能把范围内计数描述为全库计数。
- 正式→暂存仅在快照含“明确冲突”，或登记簿状态历史的原因明确写出“被替代、停用、不再使用”等事实时提出建议。
- 单独的“失败”只计为反例，不自动触发正式→暂存。
- 暂存→候选只在用户明确要求重新观察该记忆时提出建议；没有明确的重新观察请求不恢复暂存记忆。
- 所有申请在报告阶段都只是建议，必须由用户明确批准后才由本 Skill 写入阶段记忆、按全量快照重建登记簿索引并追加状态历史；历史 README 快照永不回写。

## 登记簿

`memories/记忆登记簿.md` 是统计投影和状态历史，不是快照事实源。推荐格式：

```markdown
## 记忆索引
| 记忆ID | 阶段 | 当前状态 | 采用期数 | 结果支持期数 | 结果反例期数 | 观察期数 | 涉及期数 | 最近复核日期 |

## 状态历史
| 日期 | 记忆ID | 原状态 | 新状态 | 原因 | 依据 |
```

脚本可用全库快照重建的计数校验索引；登记簿缺失时报告证据不完整，但不把手工数字当成统计事实。状态历史表中的记录只允许在用户批准后写入，因此不再增加单独的“用户批准”字段；不复制到历史 README。
