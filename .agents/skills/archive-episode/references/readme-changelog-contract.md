# 单期 README Changelog 契约

Changelog 记录已经确认、会影响本期结果或以后创作的决策与变更。它是聊天结论进入长期记忆前的持久依据，不是逐次编辑流水账。

## 位置与格式

Changelog 固定放在 `## 数据分析` 之后、`## 文档索引` 之前：

```markdown
## Changelog

| 日期 | 阶段 | 类型 | 决策或变更 | 原因 | 依据 |
| --- | --- | --- | --- | --- | --- |
| YYYY-MM-DD | 写作大纲 | 变更 | 删除第二个科学原理，只保留一个主原理 | 信息过密，影响理解 | [最终大纲](./output/大纲.md)，用户已确认 |
```

空表可保留一行：

```markdown
| — | — | — | 暂无已确认记录 | — | — |
```

添加第一条真实记录时删除该占位行。

## 允许值

- `阶段`：选题、简要架构、资料补全、写作大纲、口播文稿、发布物料、归档、记忆整理。
- `类型`：决策、变更、否决、记忆写入。
- `日期`：实际确认或写入日期，格式为 `YYYY-MM-DD`。

## 应记录

- 用户明确确认的创作决定。
- 草稿到最终版本之间有意义的改变及原因。
- 被明确否决、值得避免重复提出的方案及原因。
- 用户明确作出的频道长期决定。
- 每个记忆 Skill 实际完成的写入及来源。

## 不应记录

- 错别字、标点、排版和普通格式调整。
- 未进入讨论的临时试写。
- 命令、脚本、工具运行或校验过程。
- AI 推测的动机、效果或因果关系。
- 未获用户确认的结论。
- 只完成审计但没有发生写入的步骤。

## 依据规则

- 优先使用 README 内的确认节点或指向本期最终文件的相对 Markdown 链接。
- 用户明确宣布的长期规则可以写“用户于 YYYY-MM-DD 明确确认”；不得伪造成文件证据。
- Git 差异只能作为“发生了这项变化”的补充依据，不能单独填写原因。
- 同一日期、阶段、类型和决策内容完全相同的记录只保留一条。

## 写入权限

- `archive-episode` 可以写入归档记录和本次对话中已明确确认的重要决定。
- 三个记忆 Skills 只能追加各自成功写入的 `记忆写入` 记录。
- 任何记忆 Skill 都不得改写已有 Changelog 决策、补充未确认原因或删除历史记录。
