# 单期影片记忆同步

## 目标与边界

将单期 README 中已确认、可复核的事实投影为跨期决策索引。

- `project/<episode>/README.md` 是单期事实源，记录完整过程、原始数据和完整分析。
- `memories/往期影片信息记录.md` 是派生索引，只保存摘要、已验证结论、失败经验和待验证动作。
- 本技能只写入往期影片记忆；成功写入后仅可向单期 README 的 Changelog 追加一条 `记忆写入` 记录，绝不反向修改其他事实、逐字稿、素材或原始数据。
- `project/example/README.md` 是模板，永远不得作为同步来源。

详细字段规则见：

- [单期 README 数据契约](references/readme-contract.md)
- [长期记忆数据契约](references/memory-contract.md)
- [同步预览模板](templates/sync-preview.md)
- [跨平台安装与验证](references/platform-installation.md)
- [归档工作流契约](../archive-episode/references/workflow-contract.md)

## 何时运行

仅在用户明确要求以下操作时运行：

- 预览或同步指定 `episode_id` / 项目目录。
- 审计所有已归档影片。
- 在 README 已更新后，刷新长期记忆中的指标摘要或结论。
- 接收 `archive-episode` 完成归档后的内部交接。

不得因读取 README、撰写文稿、讨论选题、创建项目或发现一个归档目录而自动运行。同步不是创作阶段的副作用。

## 归档工作流中的交接

通过 `archive-episode` 进入时，先完整读取共享工作流契约，再执行本技能的阶段 A。向用户说明时只使用日常语言：说清准备记录哪些本期信息、依据是什么、哪些内容不会记录，不展示 Skill 名、Schema、哈希、字段映射、脚本或预览编号。

本技能在正常路径中只暂停询问一次：

- 有变更时，说明准备加入或更新的内容，然后询问是否写入。
- 无变更、重复或证据不足时，说明不会修改，并询问是否继续检查大纲和文稿经验。
- 用户批准后立即完成本步写入与回读检查，再自动执行 `creative-memory-sync`。
- 直接调用本技能时，完成自身任务后停止，不自动触发其他技能。

阻断性资料缺失和写入错误可以要求补充或停止，不计作正常批准点。

## 平台无关约束

1. 将仓库根目录解析为同时包含 `project/` 与 `memories/` 的最近祖先目录；不得假设当前工作目录固定。
2. 使用相对 Markdown 链接指向单期 README，链接形式为 `../project/<目录名>/README.md`。
3. 不依赖特定 IDE 的规则、环境变量、专属工具调用或 shell 功能。
4. 没有文件写入权限时，只能输出预览与阻断报告，不得建议复制一份长期记忆到其他位置。
5. 任何脚本只做校验；结论提炼、差异生成与写入决定均需由具备文本理解能力的 agent 按本协议执行。

## 两阶段同步协议

### 阶段 A：读取、校验与预览

按以下顺序执行，且此阶段绝不写文件：

1. 确定目标范围：单期请求只读取目标 README；全量请求扫描 `project/*/README.md` 并排除 `example`。
2. 读取目标 README、长期记忆文件，以及本技能的两个数据契约。
3. 为每个候选 README 提取身份、定位、确认结果、发布结果、原始数据摘要和分析结论。
4. 验证 `episode_id`、归档状态、发布字段组合、确认节点、数据来源、统计周期、结论状态、回链及重复条目。
5. 将候选条目归类为：`新增`、`更新`、`无需变更`、`跳过` 或 `阻断`。
6. 对 `新增` 和 `更新`生成纯投影：不得扩写 README 未表达的原因、效果或结论。
7. 使用 [同步预览模板](templates/sync-preview.md) 输出旧值、新值、来源字段、理由和明确的待确认范围。

### 阶段 B：确认后写入与回读

只有用户清晰确认预览中的 `episode_id` 范围后，才能写入。

1. 写入前重新读取目标 README 与长期记忆。
2. 若任一内容与预览快照不同，立即废弃预览并回到阶段 A；不得将旧预览直接写入新文件。
3. 对每个 `episode_id` 只维护一个长期记忆条目：首次归档新增，后续数据或结论更新该条目。
4. 一次确认只写入用户确认的可同步集合；被阻断、跳过或未确认的条目保持不变。
5. 写入后回读长期记忆，并运行只读校验。
6. 校验通过后，向本期 README Changelog 追加一条 `记忆写入` 记录；不得改写已有决策或原因。
7. 回读 README，并运行 `archive-episode/scripts/validate_memory_workflow.py --stage archive` 检查 Changelog。
8. 仅当主键、回链、权威字段、配额口径、指标标签和 Changelog 全部通过时，报告同步完成。

## 事实优先级与投影规则

单期 README 的下列字段是权威值：`episode_id`、最终标题、发布时间、发布平台、视频链接、视频时长、原始数据记录和数据分析。

- 长期记忆与权威字段冲突时，预览中提出以 README 修正长期记忆，仍需确认才可写入。
- 分析结论变化时，先由创作流程更新 README，再执行本技能；不得把仅在长期记忆中出现的文字当成新事实。
- 原始数据只留在 README。长期记忆的数字最多保留一个指标快照，并必须含 `统计周期=` 与 `来源=`。
- `已验证`、`失败`、`待验证`、`无法判断` 是不同状态。不得把待验证假设升级为已验证经验。
- 不得把完整 changelog、完整架构、逐字稿、原始截图、所有时间点指标或未经分析的感受复制进长期记忆。

## 阻断与降级规则

以下情况必须阻断对应条目的写入：

- `episode_id` 缺失、不匹配 `WF-YYYYMMDD-NN`，或在多个 README / 记忆条目中重复。
- 当前状态不是 `归档`。
- 已发布但缺少最终标题、平台、链接、发布时间或时长。
- 未发布、取消或暂停但缺少归档结果、原因或下一次复核动作。
- 数据摘要缺少统计周期或来源。
- 结论没有状态、证据或下一步动作。
- README 回链不存在，或长期记忆中的同 ID 条目结构不完整。

以下情况只能报告，不得自动修复或删除：

- 长期记忆存在但对应 README 不存在的孤儿条目。
- README 尚处于创作阶段。
- 旧式日期时间编号。
- 用户未确认的草稿、分析和发布信息。

## 预览与确认格式

预览必须清楚列出：

- 读取范围与快照摘要。
- 每个 `episode_id` 的分类。
- 每项新增或变更的旧值、新值、README 来源和理由。
- 被跳过或阻断的最小补充清单。
- 本次派生的最近十期圈层配额、已验证经验索引和待验证队列变化。
- 不会写入或删除的内容。

预览末尾必须提出一个直白、单一的确认问题；精确的项目和变更范围保留在内部，不要求用户阅读技术标识。例如：

> 我准备把上面这些本期信息加入往期影片记录。现在要写进去吗？

“可以”“继续”等泛泛答复只有在当前回合没有其他待确认操作且明确对应上述范围时才视为确认；否则要求用户重述 `episode_id` 范围。

无论直接调用还是归档串联流程，都不得在确认问题中展示 Skill 名、Schema、哈希、脚本、文件路径或字段映射；内部仍保留同等精度的来源和范围。

## 写入后的质量门槛

写入后必须验证：

- 每个 `episode_id` 仅出现一次。
- 每个条目都回链到真实 README。
- 长期记忆中的最终标题、发布日期和视频链接与 README 相同。
- 已发布条目的指标摘要带统计周期和来源；未发布条目不伪造指标。
- 最近十期配额只统计已发布条目，按实际发布时间倒序。
- 已验证经验与待验证队列都标明来源 `episode_id`，且不重复完整单期结论。

若校验失败，保留错误信息并停止后续同步。未经用户明确授权，不恢复、删除或重写其他历史条目。

## 完成时的输出

只报告：已同步条目、未同步原因、校验结果和下一步所需的最小动作。串联流程中按内部交接进入 `creative-memory-sync`。不要自动提交 Git；提交必须在四份记忆全部审计后另获用户明确批准。
