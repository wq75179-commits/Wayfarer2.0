# 创作经验复盘

## 何时使用

仅在用户明确要求归档某期项目、总结经验、分析 AI 与用户版本差异或复盘并整理记忆时使用。

- 普通写作、润色、讨论草稿或查看单期数据时不触发。
- 用户未说明项目时，先识别唯一目标；有多个可能项目时停止并请用户指定。
- `project/example/README.md` 永远不是目标项目。

本 Skill 统一接管本期归档、版本对比和三份阶段记忆的整理。它不再调用旧的记忆归档 Skill，也不写入项目外的影片索引或频道决策文件。

开始前阅读：

- [复盘与记忆契约](references/review-contract.md)
- 当前真实项目的 `README.md`
- README 的“复盘对照文件”、Changelog 和文档索引
- 三份 `memories/` 原始记忆文件

## 运行方式

### 1. 确定目标与模式

把用户意图分为两种：

- **归档模式**：用户明确要求归档。先核对 README 的归档事实，再进行对比和记忆预览。
- **复盘模式**：用户要求总结经验、分析或复盘。只进行对比和记忆预览，不改变 README 的归档状态。

归档模式中，先读取基础信息、创作确认、发布结果、数据分析、Changelog 和文档索引。不要根据聊天、旧记忆或 Git 修改猜测缺失事实。

归档前必须能够确认：

- `episode_id` 存在；
- 已发布项目具备最终标题、平台、链接、发布时间和时长；
- 未发布、取消或暂停项目具备终局原因和下一次复核动作；
- 本期归档结论有 README 中的事实或数据支撑。

先用日常语言展示准备写入 README 的归档内容和缺失项。用户明确批准后，才更新“当前状态”、归档确认和归档 Changelog；有缺失则停止归档写入，但用户仍可选择仅进行复盘。

### 2. 定位可比较文件

对大纲、文稿、包装分别寻找一对文件：AI 版本与用户版本。

优先级固定为：

1. README 的“复盘对照文件”表。
2. README Changelog 中明确标明版本角色的链接。
3. README 文档索引中明确标明“AI版本”“初稿”与“用户版本”“用户精修”“最终确认”的链接。
4. 用户在当前请求中明确提供的两个文件路径与角色。

不得根据文件名、修改时间、Git 差异或“看起来像最终稿”猜测版本角色。一个阶段没有明确的一对文件时，标为“无法比较”，说明缺少什么后继续其他阶段；不得用单一文件伪造对比。

用户版本是该阶段创作偏好的基准。它可以保留 AI 片段，但只要用户明确将其指定为用户版本或最终确认版，就按用户的最终选择分析。用户版本不是外部事实的替代品，数据和发布事实仍以 README 为准。

### 3. 读取现有记忆与进行对比

本 Skill 是整理写入方，为去重、编号和回读直接读取三份原始记忆文件；这不改变后续创作必须通过 `memory-query` 读取记忆的规则。

逐阶段比较，始终以用户版本为参照：

| 阶段 | 对比重点 |
| --- | --- |
| 大纲 | 核心承诺、叙事结构、逻辑推进、段落取舍、证据安排、认知负荷、行动闭环 |
| 文稿 | 开场、语气、句式、节奏、过渡、术语转译、场景细节、比喻、行动指令、AI 腔 |
| 包装 | 封面、标题、简介、关键词与文稿承诺的一致性、具体性、受众命中、夸张边界 |

每个结论都应包含：AI 的具体不足、用户的具体改进、对应位置或原句、以及能否转化为一条可复用经验。没有用户说明原因时，只能写“用户选择了这一改法”，不得替用户推断动机。

README 的数据只可作为支持或限制条件。`待验证`数据不能单独证明某种写法有效，也不能直接把候选经验升级为正式。

### 4. 生成预览并等待确认

只提出少量高价值、可直接指导下次创作的候选。不要把所有编辑差异逐条记忆化。

预览按阶段列出：

- 可比较、无法比较或无新经验；
- AI 问题与用户改进；
- 对应的 AI 文件、用户文件和 README 依据；
- 拟新增、更新、转正式或转暂存的记忆；
- 明确不会写入的低价值、一次性或证据不足差异。

新发现默认只能提出为`候选`。同义经验已存在时，不建立重复条目；说明是保留原条目、改写原条目，还是仅提示用户该候选可能已被再次验证。

状态变化只能由用户明确批准：

- 候选转正式：现有候选再次得到本次明确对比支持后，提出建议，不能自动升级。
- 正式转暂存：发现明显不再适用或与用户版本冲突时，只提出原因，不能自动降级。
- 暂存转候选：只能在用户要求重新观察时提出。

预览结尾只提出一个明确问题，允许用户按阶段、编号或条目部分批准。没有明确批准，不得写入记忆或 Changelog。

### 5. 获批后写入与回读

只处理用户批准的范围。每一条记忆必须符合 `memory-query` 的当前格式：

```markdown
### OUT-0001｜标题
阶段：大纲
状态：候选
内容：一条可直接指导创作的经验。
```

- 大纲写入 `memories/大纲记忆.md`，编号为 `OUT-xxxx`。
- 文稿写入 `memories/文稿记忆.md`，编号为 `SCR-xxxx`。
- 包装写入 `memories/包装记忆.md`，编号为 `PKG-xxxx`。
- 每条只写一个阶段；跨阶段经验必须拆开后分别批准。
- 新编号取对应文件现有最大编号后的下一个，不复用删除过的编号。
- 不删除记忆，不自动覆盖冲突记忆；存在冲突时停止该条并请用户选择。

写入前重新读取本期 README、所有对照文件和三份记忆。任何来源变化都使旧预览失效，必须重新展示。

写入后重新读取三份记忆，确认：编号唯一、编号前缀正确、阶段与文件一致、状态有效、内容非空且没有多阶段条目。只有实际写入成功后，才向本期 README 的 Changelog 追加一条 `阶段=记忆整理`、`类型=记忆写入` 的记录，并列明写入的编号与对照来源。

若当前步骤的记忆写入、README 追加或回读检查失败，恢复本步骤开始前的目标记忆文件和 README，然后停止并报告失败原因。不得改写既有 Changelog，也不得撤销此前已获批且检查通过的步骤。

## 完成时报告

完成后只说明：归档是否完成、各阶段是否可比较、AI 的主要改进方向、已写入或未写入的记忆编号、用户未批准项和检查结果。不要把一次文稿获批描述成其中全部写法已经成为正式规则。
