# 复盘与记忆契约

本契约约束 `creative-memory-review` 如何从用户版本中学习，同时保留用户对长期记忆的最终决定权。

## 1. 事实与偏好

| 内容 | 权威来源 | 不可替代来源 |
| --- | --- | --- |
| 单期事实、发布数据、状态 | `project/<项目>/README.md` | 旧记忆、聊天推测、Git 历史 |
| 用户的创作偏好与修正方向 | 明确标识的用户版本、README 确认和 Changelog | AI 自评、文件名、修改时间 |
| 长期阶段经验 | 三份 `memories/` 文件中经用户批准的条目 | 一次草稿完成、一次发布、未经批准的候选 |
| 本期涉及的记忆与本期结果 | README Changelog 的“本期相关记忆（快照）” | 普通 Changelog 的聚合句、旧记忆推测 |
| 跨期统计与当前状态投影 | `memories/记忆登记簿.md`（从各期快照汇总）及三份阶段记忆 | 单期快照以外的自由文本、聊天推测 |

用户版本优先说明“本期最终选择了什么”，不自动说明“为什么”。没有明确原因时，报告观察到的差异即可。

## 2. 对照文件表

未来项目在 README 中使用以下表格。路径使用相对 Markdown 链接，均指向本期目录内的文件。

```markdown
## 复盘对照文件

| 阶段 | AI版本 | 用户版本 |
| --- | --- | --- |
| 大纲 | [AI大纲](./output/写作大纲_AI.md) | [用户大纲](./output/写作大纲_用户确认.md) |
| 文稿 | [AI文稿](./output/口播文稿_AI.md) | [用户文稿](./output/口播文稿_用户确认.md) |
| 包装 | [AI包装](./output/发布物料_AI.md) | [用户包装](./output/发布物料_用户确认.md) |
```

空单元格表示该阶段没有可比较文件。既有项目不补填、不猜测；用户可在执行时明确指定一对文件。

## 3. 对比输出

每个可比较阶段使用以下最小预览：

```markdown
### 文稿｜可比较

- AI问题：开场先解释背景，未在前段给出可验证的具体场景。
- 用户改进：改为先给一个具体行为，再引出解释。
- 依据：[AI文稿](...) 第 1 段；[用户文稿](...) 第 1 段；用户选择了该改法。
- 候选记忆：`SCR-0007`｜先用具体行为打开抽象问题
  - 内容：开场先给观众可识别的具体行为，再解释抽象机制。
  - 状态：候选。
```

没有明确对照、变化只是措辞微调、无法写成下次可执行动作，或只由待验证数据支持时，不生成候选。

## 4. 本期相关记忆（快照）

每个真实项目的 README 在 Changelog 下维护一张独立的最小快照表。它只回答“本期涉及了哪些记忆、当时是什么状态、本期表现如何”，不承载跨期计数或全局状态历史。

```markdown
### 本期相关记忆（快照）

| 日期 | 记忆ID | 阶段 | 状态 | 本期结果 | 依据 |
| --- | --- | --- | --- | --- | --- |
| 2026-09-02 | SCR-0007 | 文稿 | 候选 | 采用、待验证 | [用户文稿](./output/口播文稿.md) |
```

- `日期`使用本次复盘或复核日期；`记忆ID`、`阶段`和`状态`必须与阶段记忆条目一致。新记忆固定从`候选`开始。
- `状态`是本期复盘时的历史快照，不是登记簿的全局当前状态。后续状态迁移不回写历史快照。
- `本期结果`只使用以下固定标签，并可组合：`采用`、`已验证`、`失败`、`待验证`、`无法判断`、`明确冲突`、`未采用`。
- `采用`只表示用户在本期选择或批准该写法；不得因此填写`已验证`。`已验证`和`失败`分别用于效果支持与反例，`待验证`或`无法判断`表示没有足够结果证据。
- 同一 README 中同一记忆 ID 只保留一行。再次复核时更新该行，不追加重复行或长事件表。
- `依据`使用能回溯本期判断的相对链接，例如 AI/用户版本或 README 数据记录；不要把登记簿计数复制到快照中。
- 普通 Changelog 表继续记录本期其他决策，不重复记录记忆操作。旧 README 中没有记忆 ID 的自然语言记录保留为历史事实，标记为“历史未结构化”，不自动计数或映射。

## 5. 记忆状态

| 状态 | 含义 | 谁能改变 |
| --- | --- | --- |
| 候选 | 值得在后续项目继续观察的经验 | 用户批准创建、修改或恢复 |
| 正式 | 用户确认可稳定参考的经验 | 用户批准升级或修改 |
| 暂存 | 用户准备停止使用、但尚可复查的经验 | 用户批准转入或恢复 |

- 新结论一律从候选开始。
- 某候选在新的对比中再次出现时，AI 可以提示用户复核是否升级，但不得声称自动达到次数门槛。
- 正式记忆可能与新用户版本冲突时，AI 只能提出暂存建议。
- 不删除条目。删除需求先改为暂存，并向用户说明原因；用户要求恢复时改回候选重新观察。
- 阶段记忆文件保存当前状态，README 快照保存单期状态；两者不能互相覆盖历史事实。

## 6. 编号与文件

| 阶段 | 文件 | 编号 |
| --- | --- | --- |
| 大纲 | `memories/大纲记忆.md` | `OUT-0001` 起 |
| 文稿 | `memories/文稿记忆.md` | `SCR-0001` 起 |
| 包装 | `memories/包装记忆.md` | `PKG-0001` 起 |

条目最小格式：

```markdown
### SCR-0001｜标题
阶段：文稿
状态：候选
内容：一条可直接指导创作的经验。
```

一条只能属于一个阶段。经验影响多个阶段时，拆为各阶段独立条目，分别获得用户批准。历史项目、来源和验证证据保存在 README 快照与登记簿，不复制进记忆条目。

## 7. 批准与回退

1. 先展示归档预览或记忆预览，不写入。
2. 用户可批准全部、某阶段、某些条目或拒绝。
3. 写入前重读来源；来源变动则废弃预览。
4. 写入获批的阶段记忆，并新增或更新本期 README 的快照行；不要追加长事件表。
5. 按 `记忆ID + episode_id` 去重汇总登记簿的采用、已验证、失败和观察计数；只有用户明确批准状态迁移时才更新登记簿状态历史。
6. 写入后回读全部阶段记忆、本期 README 和登记簿；任一步骤失败时恢复本步骤的文件快照并停止。

无新增或更新、用户拒绝、来源不明或校验失败时，不写快照，也不改变登记簿。历史快照一经写入不得由后续跨期整理改写。
