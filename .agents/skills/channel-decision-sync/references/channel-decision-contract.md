# 频道重大决策数据契约

`memories/重大决策记忆.md` 记录影响频道方向的长期决定，不记录单期执行细节或从数据中推测的策略。

## 收录门槛

同时满足以下条件才能提出写入：

1. 用户明确表达已经作出决定，而非仍在讨论建议。
2. 决定会影响未来多个项目、频道定位、受众、内容比例、风格规则、资源分配或工作流程。
3. 决定已记录在本期 README Changelog。
4. 能说明影响范围和生效时间；用户未说明原因时如实保留“未说明”。

以下内容不得收录：

- 单期标题、封面、结构和句子修改。
- 一次播放数据或未经复核的表现判断。
- agent 推断的用户偏好或建议。
- 只在聊天出现、尚未写入 Changelog 的内容。
- 与已有决定同义但没有新增信息的复述。

## 决策格式

沿用现有编号并递增，不复用已废弃编号：

```markdown
### D003：决策标题

- **决策日期**：YYYY-MM-DD
- **决策内容**：用户明确决定的内容
- **决策原因**：明确原因；未说明时写“未说明”
- **影响范围**：选题 / 风格 / 受众 / 圈层比例 / 工作流程 / 其它
- **生效起始**：从 WF-YYYYMMDD-NN 开始
- **状态**：🟢 执行中 / 🟡 待观察 / 🔴 已废弃
- **来源项目**：[WF-YYYYMMDD-NN](../project/<目录>/README.md)
- **回顾评价**：待后续复核
```

既有 D001、D002 等历史条目没有来源项目字段时保持原样，不进行追溯补写。

## 状态规则

- `🟢 执行中`：用户已经决定实施，是否有效可以以后复核。
- `🟡 待观察`：决定已作出，但用户明确要求先试行或等待结果。
- `🔴 已废弃`：用户明确停止该决定，或新决定明确替代它。

“缺少数据”不能自动把执行中改为待观察；“表现不好”也不能自动废弃决定。状态变化必须来自用户明确确认。

## 更新与冲突

- 同一决定的新证据写入回顾评价，不创建重复编号。
- 新决定替代旧决定时，新建编号，并在旧决定中标明废弃日期、原因和替代编号。
- 发现两个执行中决定冲突时停止写入，用日常语言请用户选择，不自行合并。
- 与本期无关的旧格式或缺失只报告，不在例行流程中重写。

## Changelog 回写

只有重大决策记忆实际写入并回读通过后，才向本期 README 追加：

```markdown
| YYYY-MM-DD | 记忆整理 | 记忆写入 | 整理频道重大决策：D003 <标题> | 用户已批准 | [本期 README](./README.md) |
```

没有新决定时不写入 Changelog，也不更新时间。
