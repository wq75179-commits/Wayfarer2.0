# 创作记忆数据契约

本契约规定本期项目如何更新大纲与文稿两份长期记忆。两份文件保存跨期规律，不是单期复盘副本。

## 共同来源格式

所有新增长期记忆或待观察项必须保留真实 `episode_id`：

```markdown
（来源：WF-YYYYMMDD-NN）
```

同一模式再次出现时，在原条目增加新的来源，不创建同义条目：

```markdown
（来源：WF-20260801-01、WF-20260815-01；出现 2 期）
```

既有初始化内容来自历史样稿，可以保留原有影片标题来源，不要求追溯改写。新流程不得把这些标题伪造成 `episode_id`。

## 三种证据等级

### 用户明确长期要求

用户明确表达“以后都这样”“这是频道规则”等长期含义，并已进入 Changelog。可以直接提出写入相关正式规则区，但仍需本技能批准。

### 单期观察

本期发生了有意义的修改，但用户没有表达长期含义。使用：

```markdown
- [待观察｜1/3] <模式与适用场景>（来源：WF-YYYYMMDD-NN）
```

不得写成“用户总是”“最佳实践”或永久禁令。

### 重复模式

同一模式必须由三个不同 `episode_id` 支持。达到三期时仍保留待观察状态，先询问用户；批准后再移入正式规则区，并保留全部来源。

## 大纲记忆映射

目标：`memories/大纲创作技巧记忆.md`

| 内容 | 首选章节 |
| --- | --- |
| 开场与钩子 | 一、钩子/开场经验 |
| 科学原理与证据组织 | 二、科学锚点使用记录 |
| 比喻与对应动作 | 三、比喻库 |
| 非标准结构 | 四、结构变体经验 |
| 用户修改模式与单期观察 | 五、用户修改模式（我的盲区） |
| 选题公式与失败方向 | 六、选题切入经验 |

单期观察优先放在第五节的当前修改记录中；只有获得用户明确长期确认后，才移动到相应正式经验区。

## 文稿记忆映射

目标：`memories/文稿撰写记忆.md`

| 内容 | 首选章节 |
| --- | --- |
| 新的长期写作规则与待观察模式 | 一、风格校准补丁 |
| 用户保留或新增的代表性句子 | 二、好句收集 |
| 用词、句式与过渡偏好 | 三、用户表达偏好 |
| 重复发生的写作错误 | 四、我的常犯错误 |
| 各幕、段落与收束经验 | 五、段落级经验 |

一条好句只有在用户明确认为值得复用，或最终稿保留且 Changelog 明确指出其价值时才收录。不得仅凭 agent 自评把自己的句子加入好句库。

## 去重与更新

- 先按含义查找现有条目，再决定新增或更新。
- 同一 `episode_id` 在同一条经验的来源中只出现一次。
- 同义表达合并时保留各来源，不改变原意，不顺手合并与本期无关的历史条目。
- 被明确否决的做法先记录适用场景；除非用户宣布为长期禁用规则，不扩大适用范围。
- 数据表现可以作为限制或复核线索，但不能单独证明某个写法有效。

## Changelog 回写

仅在至少一份创作记忆实际写入且回读通过后追加：

```markdown
| YYYY-MM-DD | 记忆整理 | 记忆写入 | 整理大纲经验：<摘要>；整理文稿经验：<摘要> | 用户已批准 | <来源链接或 README Changelog 行> |
```

未更新的那一类写“无变更”只用于对话结果，不写入 Changelog。
