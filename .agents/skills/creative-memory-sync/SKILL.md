# 创作经验记忆整理

## 目标与写入边界

从一个已归档项目提炼可追溯的创作经验，同时避免把一次特殊处理夸大为长期偏好。

- 只写 `memories/大纲创作技巧记忆.md`、`memories/文稿撰写记忆.md`，以及本期 README 的一条成功写入日志。
- 不写往期影片索引，不写频道重大决策，不修改本期大纲、文稿或已有 Changelog 决策。
- 两份创作记忆在同一个询问中分别展示；用户可以只批准其中一份或部分条目。

执行前完整读取：

- [创作记忆契约](references/creative-memory-contract.md)
- [归档工作流契约](../archive-episode/references/workflow-contract.md)
- 当前真实单期 README、两份目标记忆，以及 Changelog 明确指向的本期最终文件。

## 整理流程

### 1. 验证入口

1. 确认目标不是 `project/example/README.md`。
2. 确认 `episode_id` 合法、当前状态为归档、归档已确认。
3. 在串联流程中，确认内部交接来自已完成的 `episode-memory-sync`；直接调用时要求用户明确指定一期项目。
4. 重新读取所有来源，不信任上一步缓存的内容。

### 2. 生成候选

只从 Changelog 已确认记录及其引用文件提取：

- 大纲结构、开场、科学锚点、比喻、选题切入与用户修改模式。
- 文稿用词、句式、过渡、段落写法、保留好句与常犯错误。
- 明确的长期要求、单期观察、重复出现的模式和明确否决。

对每项候选标明：准备加入或更新的位置、本期依据、当前出现次数、是长期规则还是待观察。相同经验已经存在时更新来源和次数，不另建同义条目。

不得提取：只有聊天表述但未进入 Changelog 的内容、没有原因的 Git 变化、纯格式修改、AI 自己的评价，以及只由播放数据推测出的写作因果。

### 3. 唯一正常暂停点

用日常语言分别说明：

- 大纲方面准备记下什么、依据是什么、哪些不记录。
- 文稿方面准备记下什么、依据是什么、哪些不记录。

然后只问一次，例如：

> 我准备把这两条大纲经验和一条文稿修改习惯记下来，依据都来自你确认过的修改。另有一条只有一次现象，我会保留为待观察。现在要写进去吗？

不要展示 Skill 名、字段名、脚本、计数格式或文件内部结构。没有有效候选时也要说明，并询问是否继续检查频道长期决定。

### 4. 批准后写入

1. 重新读取 README、来源文件和两份目标记忆；内容变化时废弃旧说明并重新整理。
2. 只写用户批准的条目。单次观察标明来源期数但不升级为固定规则；三个不同项目重复后才提出升级。
3. 保持目标文档现有章节和风格，只更新最相关的位置，不重排无关历史。
4. 成功写入后，在本期 README Changelog 追加一条 `记忆写入` 记录；两份文件都更新时可用一条记录分别说明。
5. 回读并运行：

```powershell
rtk python -B -X utf8 .agents/skills/creative-memory-sync/scripts/validate_creative_memory.py --repo-root . --episode <README路径>
```

当前步骤任一文件未通过时，恢复本步骤开始前的两份记忆与 Changelog，停止流程并报告问题。

### 5. 内部交接

在串联流程中，写入成功或确认无变更后，按工作流契约立即执行 `channel-decision-sync`。直接调用本技能时完成自身检查后停止，不自动进入下一步。

## 完成条件

- 两份创作记忆都已审计。
- 获批条目均有本期来源，不重复、不越级升级。
- 未获批、证据不足和与本期无关的历史内容保持不变。
- 写入后的目标与 Changelog 回读检查通过。
